# PRD - DataPersistence PoC
## 제품 요구사항 정의서

**프로젝트**: DataPersistence PoC  
**작성일**: 2026-06-12  
**대상 엔티티**: Sample (시료), Order (주문), 재고 (Stock)

---

## 1. 목적

사용자는 프로그램을 종료하고 재시작한 후에도 이전에 입력한 시료 데이터, 주문 데이터, 재고 수량을 그대로 유지하고 조회할 수 있어야 한다.

---

## 2. 사용자 요구사항

### 2-1. 시료 등록
- 사용자는 새로운 시료를 시스템에 등록할 수 있어야 한다.
- 사용자는 시료 등록 시 ID, 이름, 평균 생산시간, 수율을 입력할 수 있어야 한다.
- 사용자는 이미 존재하는 ID로 시료를 등록하려 할 경우 오류 안내를 받아야 한다.
- 사용자는 등록된 시료가 프로그램 종료 후에도 보존됨을 신뢰할 수 있어야 한다.

### 2-2. 시료 전체 조회
- 사용자는 등록된 모든 시료 목록을 한 번에 확인할 수 있어야 한다.
- 사용자는 각 시료의 ID, 이름, 평균 생산시간, 수율, 현재 재고를 목록에서 확인할 수 있어야 한다.
- 사용자는 프로그램을 재시작한 후에도 이전에 등록된 시료 목록을 동일하게 확인할 수 있어야 한다.

### 2-3. 시료 단건 조회
- 사용자는 특정 시료 ID를 입력하여 해당 시료의 상세 정보를 조회할 수 있어야 한다.
- 사용자는 존재하지 않는 ID로 조회 시 해당 시료가 없다는 안내를 받아야 한다.

### 2-4. 시료 수정
- 사용자는 기존에 등록된 시료의 속성(이름, 평균 생산시간, 수율, 재고)을 수정할 수 있어야 한다.
- 사용자는 수정 내용이 저장된 후 프로그램을 재시작해도 수정된 값이 그대로 유지됨을 확인할 수 있어야 한다.
- 사용자는 존재하지 않는 ID를 수정하려 할 경우 오류 안내를 받아야 한다.

### 2-5. 시료 삭제
- 사용자는 특정 시료를 시스템에서 삭제할 수 있어야 한다.
- 사용자는 삭제 후 해당 시료가 목록에서 사라짐을 확인할 수 있어야 한다.
- 사용자는 프로그램을 재시작한 후에도 삭제된 시료가 복원되지 않음을 확인할 수 있어야 한다.
- 사용자는 존재하지 않는 ID를 삭제하려 할 경우 오류 안내를 받아야 한다.

### 2-6. 주문 등록
- 사용자는 새로운 주문을 시스템에 등록할 수 있어야 한다.
- 사용자는 주문 등록 시 시료 ID, 고객명, 주문 수량을 입력할 수 있어야 한다.
- 사용자는 등록된 주문에 자동 생성된 주문번호(예: ORD-20260416-0001)가 부여됨을 확인할 수 있어야 한다.
- 사용자는 등록된 주문의 초기 상태가 RESERVED임을 확인할 수 있어야 한다.
- 사용자는 등록된 주문이 프로그램 종료 후에도 보존됨을 신뢰할 수 있어야 한다.

### 2-7. 주문 전체 조회
- 사용자는 등록된 모든 주문 목록을 한 번에 확인할 수 있어야 한다.
- 사용자는 각 주문의 주문번호, 시료 ID, 고객명, 주문 수량, 상태를 목록에서 확인할 수 있어야 한다.
- 사용자는 프로그램을 재시작한 후에도 이전에 등록된 주문 목록을 동일하게 확인할 수 있어야 한다.

### 2-8. 주문 단건 조회
- 사용자는 특정 주문번호를 입력하여 해당 주문의 상세 정보를 조회할 수 있어야 한다.
- 사용자는 존재하지 않는 주문번호로 조회 시 해당 주문이 없다는 안내를 받아야 한다.

### 2-9. 주문 상태 수정
- 사용자는 기존 주문의 상태를 변경할 수 있어야 한다.
- 사용자는 PRODUCING 상태 주문에 한해 실제 생산 수량, 생산 시작 시간, 총 생산 시간을 설정할 수 있어야 한다.
- 사용자는 상태 변경 내용이 저장된 후 프로그램을 재시작해도 변경된 값이 그대로 유지됨을 확인할 수 있어야 한다.
- 사용자는 존재하지 않는 주문번호를 수정하려 할 경우 오류 안내를 받아야 한다.

### 2-10. 주문 삭제
- 사용자는 특정 주문을 시스템에서 삭제할 수 있어야 한다.
- 사용자는 삭제 후 해당 주문이 목록에서 사라짐을 확인할 수 있어야 한다.
- 사용자는 프로그램을 재시작한 후에도 삭제된 주문이 복원되지 않음을 확인할 수 있어야 한다.
- 사용자는 존재하지 않는 주문번호를 삭제하려 할 경우 오류 안내를 받아야 한다.

### 2-11. 재고 수량 조회
- 사용자는 특정 시료의 현재 재고 수량을 조회할 수 있어야 한다.
- 사용자는 프로그램을 재시작한 후에도 재고 수량이 이전과 동일하게 유지됨을 확인할 수 있어야 한다.

### 2-12. 재고 수량 변경
- 사용자는 시료의 재고 수량을 직접 변경(증가/차감)할 수 있어야 한다.
- 사용자는 재고 수량이 변경된 즉시 저장되어 프로그램 재시작 후에도 변경된 수량이 유지됨을 확인할 수 있어야 한다.
- 사용자는 재고 수량이 0 미만으로 설정되는 경우 오류 안내를 받아야 한다.

---

## 3. 데이터 영속성 요구사항

- 사용자는 프로그램이 정상 종료된 후 재시작하더라도 기존 데이터가 유실되지 않음을 기대할 수 있어야 한다.
- 사용자는 데이터가 어디에 저장되는지 설정을 통해 파악하거나 변경할 수 있어야 한다.

---

## 4. 범위 외 항목 (Out of Scope)

- 복수 사용자 동시 접근 시나리오는 고려하지 않는다.
- 네트워크 기반 저장소 연동은 포함하지 않는다.
- 주문 승인/거절, 생산라인 자동 스케줄링 등 비즈니스 로직은 본 PoC 범위에 포함되지 않는다.
