# FEATURE-09: 재고 관리 영속성 (Stock Persistence)

## 기능 목적

시료별 실제 재고(물리적 재고) 수량이 항상 정확하게 저장되고, 프로그램 재시작 후에도 동일한 재고 수량을 복원할 수 있도록 한다.

재고는 스펙에 직접 명시되지 않은 구현 필수 항목으로, 주문 처리(출고, 생산 완료) 과정에서 재고 수량이 변동될 때 해당 변경이 즉시 영구 저장되어야 한다.

---

## 배경

재고(stock)는 시료(Sample) 엔티티의 속성으로 관리된다.  
재고 수량 변동은 주로 아래 이벤트에 의해 발생한다:

| 이벤트 | 재고 변동 |
|--------|-----------|
| 출고 처리 (CONFIRMED → RELEASE) | 주문 수량만큼 재고 차감 |
| 생산 완료 (PRODUCING → CONFIRMED) | 실생산량만큼 재고 증가 |
| 시료 수정 (직접 수정) | 관리자가 직접 재고 수량 설정 |

---

## 사용자 시나리오

### 재고 조회
1. 사용자가 재고 조회 메뉴를 선택한다.
2. 시스템이 시료별 현재 재고 수량을 표시한다.
3. 프로그램을 재시작해도 동일한 재고 수량이 표시된다.

### 재고 변경 (직접 수정)
1. 사용자가 재고 수정 대상 시료 ID를 입력한다.
2. 사용자가 변경할 재고 수량을 입력한다.
3. 시스템이 재고 수량을 즉시 저장한다.
4. 프로그램을 재시작해도 변경된 재고 수량이 유지된다.

---

## 입력

| 항목 | 타입 | 제약 |
|------|------|------|
| 시료 ID | 문자열 | 필수 |
| 재고 수량 | 정수 | 0 이상 |

---

## 출력

- 조회 시: 시료별 ID, 이름, 현재 재고 수량 표시
- 변경 성공 시: 변경 완료 안내 및 변경된 재고 수량 표시
- 실패 시: 오류 안내 메시지 표시

---

## 예외 처리

| 상황 | 처리 방식 |
|------|-----------|
| 존재하지 않는 시료 ID | 오류 안내 메시지 표시 |
| 재고 수량이 음수 | 오류 안내 후 재입력 유도 |

---

## 영속성 보장 조건

- 재고 수량 변경이 발생하는 모든 시점에 즉시 JSON 파일에 저장해야 한다.
- 프로그램이 비정상 종료되더라도, 마지막으로 저장된 재고 수량이 다음 실행 시 복원되어야 한다.
